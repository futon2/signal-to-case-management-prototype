# 業務フロー統合型・予兆管理プラットフォーム プロトタイプ

英語名: Business Flow & Signal Management Platform

相談～見積、プロジェクト、保守・運用を3つの業務ステップとして可視化する説明用プロトタイプです。各ステップの履歴を蓄積し、要注意シグナルと疑似AI支援で、本部長・幹部が早めにリスクと将来売上を把握できる形を示します。

## 起動方法

ビルドやインストールは不要です。

1. `index.html` をブラウザで開く
2. 左ナビゲーションから画面を切り替える
3. 入力データはブラウザの `localStorage` に保存される
4. 初期状態に戻す場合は左ナビ下部の「データ初期化」を押す

ローカルサーバから開きたい場合:

```powershell
cd C:\Users\takah\Documents\Codex\signal-to-case-management-prototype
python -m http.server 5173
```

その後、ブラウザで `http://localhost:5173` を開いてください。

## データモデル

型定義は [types.ts](./types.ts) に記載しています。

主なモデル:

- `RequestItem`: 正式案件になる前の相談～見積入口
- `RequestHistory`: 相談メモの履歴
- `Estimate`: 相談に紐づく見積。1相談に複数版を持てる
- `EstimateHistory`: 見積前提、指摘、コメントの履歴
- `Project`: 発注後に開始されるプロジェクト
- `ProjectUpdate`: 週次 / 月次のプロジェクト更新履歴
- `ProjectPlan`: マイルストーン、会議、見積、リリースなどのプロジェクト予定
- `OperationSystem`: 本番稼働後の保守・運用対象
- `OperationHistory`: 問い合わせ、障害、小改修、監査対応などの履歴
- `Signal`: 各フェーズで発生する違和感・兆し・要注意シグナル

## ライフサイクル

基本の流れは以下です。

```text
相談～見積
  ↓
プロジェクト
  ↓
保守・運用
```

各フェーズは1回の入力で終わりません。

- 相談～見積では、相談メモ、見積版、指摘・コメントを履歴として蓄積できます。
- プロジェクト詳細では予定と週次 / 月次更新を複数回追加できます。
- 保守・運用詳細では保守メモ、問い合わせ、障害、小改修、監査対応を複数回追加できます。

詳細画面はタブ表示にしており、過去の経緯を「履歴」「予定」「見積経緯」「関連シグナル」などの観点で切り替えて確認できます。AI要約・示唆は画面を占有しないよう、クリックで開く折りたたみ表示にしています。

## 経営ダッシュボード

経営ダッシュボードは、件数一覧ではなく、経営層が短時間で判断するための画面として再設計しています。

主な判断軸:

- `需要・売上見通し`: 12か月予測売上、受注確度、年度予算との差、月別業務量
- `正社員要員`: 月別要員過不足、スキル別不足、PM兼務、代替要員不足
- `外注・パートナー最適化`: 必要外注人月、未確保人月、推奨パートナー、外注費
- `プロジェクト採算・健全性`: 採算危険案件、悪化案件、工数超過、追加見積未合意
- `重大障害・重要トラブル対応`: 対応中重大障害、期限超過対応、暫定復旧のみ、再発防止未完了

画面上部には、表示ビュー、対象期間、対象組織、金額規模、状態、売上確度の共通フィルタを置いています。対象期間は月別チャート、売上確度は売上KPIと内訳、状態は採算ランキングと重大障害一覧に反映します。右側の表示設定パネルでは、5つの判断軸ごとに表示項目をチェックボックスで切り替えられます。

ダッシュボード本文の最上段には、当年から3年後までの半年別売上見通しを置いています。相談～見積、プロジェクト、保守・運用の売上を積み上げ、合計売上が増えそうか減りそうかを最初に確認できます。

初期表示の主要KPI:

- 12か月予測売上: 42.8億円
- 正社員不足人月: 68人月
- 必要外注人月: 68人月
- 採算危険プロジェクト: 6件
- 対応中重大障害: 4件

表示ビューは、全社経営ビュー、需要・要員ビュー、外注最適化ビュー、採算管理ビュー、重大障害ビュー、幹部会前ビューを用意しています。表示設定を変更した状態は、保存ビューとして localStorage に保持できます。

## 要注意シグナル

シグナルは、正式な課題になる前の小さな違和感です。相談～見積、プロジェクト、保守・運用のどのステップにも紐づけられます。

疑似AIは以下を行います。

- キーワードからカテゴリを推定
- 深刻度、頻度、カテゴリ、関連対象からリスクスコアを算出
- 70点以上を要注意シグナル候補にする
- 85点以上を幹部会報告候補にする
- 本部長確認候補または幹部会報告候補を推奨

## 疑似AI機能

実AI APIは使っていません。`app.js` 内の関数で疑似的に処理しています。

- シグナル分類
- リスクスコア算出
- 見積説明文案
- 不足前提の提示
- 類似過去見積の提示
- プロジェクト更新の要約
- 状態軸の変化推定
- プロジェクト予定の次予定表示
- 保守・運用負荷の要約
- AI質問画面のダミー回答

## 初期版と本番化の違い

| 項目 | 初期版 | 本番化 |
| --- | --- | --- |
| データ | フロントエンド内のダミーデータと localStorage | 既存システム、Excel、PowerPoint、Teams、SharePoint 連携 |
| AI | 疑似AI関数 | OpenAI / Azure OpenAI による分類、要約、類似検索 |
| 見積支援 | 前提・除外事項・説明文のダミー提示 | 過去見積DB、見積Excel、WBS標準との連携 |
| プロジェクト把握 | 週次更新とシグナルで把握 | 資料、メール、工数、課題表から自動抽出 |
| 保守運用 | 件数と履歴を手入力 | 問い合わせ管理、障害管理、J-SOX証跡管理と連携 |
| 権限 | なし | 本部長、幹部、部課長、担当者で閲覧範囲を分離 |

## 注意事項

このプロトタイプは、現場に新たな重い報告業務を課すものではありません。

- 目的は監視ではなく、業務フローの可視化と早期支援
- 入力はできるだけ軽くする
- 相談・見積・プロジェクト・保守運用の履歴を自然に蓄積する
- AIは現場を評価するためではなく、要約・分類・見積支援・予兆検知を支援するために使う
- 本番化時は権限管理、個人情報、健康情報、監査情報の取り扱いを厳格に設計する

## 技術メモ

既存機能を活かすため、React / Vite へは移行せず、依存なしの静的 HTML/CSS/JavaScript 構成を維持しています。将来 React + TypeScript + Vite へ移行する場合は、`types.ts` の型定義を使い、`app.js` のデータ生成、疑似AI、描画処理をコンポーネントとサービス層に分割してください。
